## Review limits and outstanding candidate

The lock coordinates cooperating native versions only. Older active SDK writers
must reload. An unrelated editor can still race after the final fingerprint check;
there is no filesystem CAS or atomic multi-file transaction. Conflicting bytes and
changed-bundle recovery journals are retained; no rollback over foreign edits or
power-loss durability is claimed. A paused live owner is never displaced by age.

Task cancellation (`[-]`), handoff retirement, question identity and immutable
completion overlays are preserved from main; this connector does not redefine
them. Ending a Claude session is not an explicit native worker cancellation API.
The worker has bounded process calls; process interruption can leave a journal for
the next cooperating request. Missing Node/bootstrap, oversized metadata and
damaged native authority fail closed. Notification delivery plus acknowledgement
is best effort, rather than exactly once.

Candidate reported to root before expanding scope: [pending recovery](../../scripts/connect-transaction.ts#L195)
replays an earlier connect before a newly arrived remove reaches `run`, where its
disable intent is saved. If that remove process is interrupted during replay,
the new disable intent may not yet be durable. Existing killed-remove coverage
starts without a pending connect, so it does not prove this ordering safe. A focused
reproduction/root decision remains required; this manifest does not call it fixed.

Subsequent root-authorized focused pass reproduced this candidate, then corrected
the ordering: remove saves its disable flag before recovery, and disabled recovery
accounts for applied ownership before cleaning the original scope as remove. A
same-scope request returns that cleanup result; a different incoming scope is
handled afterward. Explicit connect may re-enable only after valid recovery.
Drift/bundle mismatch retains the journal and true disable flag. The 23-test
transaction/bootstrap file batch passed, including interruptions before/after
generated ownership recovery; see the updated chronological validation record.
The candidate paragraph above is retained as review history. Full acceptance on
this subsequent runtime change remains pending.
